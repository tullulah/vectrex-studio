- It's the regular pico sdk
- There is no HAL and I might never do any. It works more like modern GPU APIs where you record (VIA) commands in a buffer that is than executed. 
- There are currently 2 modes. One uses PIO and the other one runs just on the second core. The main reason for this is that it is easier to get things up and running on the second core. But as it blocks one core I maybe convert more of this code to PIOs at some point in the future
- The GPIOs are only connected to the Vectrex bus. So the RP2350 can either get read/write requests from the 6809. Or it can put the 6809 in halt and send read/write requets to the VIA. Technically to RAM and ROM too but there is not much benefit of this. So every drawing needs to be either done by the 6809 or by sending VIA commands like the 6809 would do
- Again there are two modes. The (or any) firmware itself can be flashed by any way that the pico supports. uf2 is the most common. Our default firmware has also the option to load and execute RAM only code from the sd card. I currently convert these from uf2 files in a more compact binary format with a custom header

One of the issues with the 6809 is that even in halt mode it still generates the clock signal. So you need to sync with it. So you monitor the clk (either with a core or PIO) and when you detect the edge you need to update the address and data io so the VIA execute your write with the next clk edge
Beside this you have to write the same values to the same via registers as any 6809 vectrex code would do
